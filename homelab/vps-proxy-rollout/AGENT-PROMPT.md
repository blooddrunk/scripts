# 从零部署 VPS 的 Agent Prompt

复制下面整段文字。先填 VPS 地址、初始 SSH 登录方式，以及有无域名和 DNS 托管商。其余可沿用默认值，Agent 会在实际需要时追问。初始密码只在交互式 SSH 或厂商控制台输入。

```text
请把下面这台已开通的空白 VPS 配置成我的代理服务器。请实际执行安装、配置、重启和验收，遇到可恢复的错误就诊断并继续。

我提供的信息
- VPS 地址或已有 SSH 别名：<公网 IP 或 SSH 别名>
- 首次 SSH 登录：<用户、端口（省略按 22）、已配密钥 / 仅密码 / 厂商控制台>。厂商或控制台入口可一并填写。
- 域名与 DNS 托管：<无域名，或可用域名 + Cloudflare / 其他托管商>。指定子域名可写在这里。
- 可选项：tcpfit=按需，1Panel=不装，关闭 3x-ui 公网直连=是（SSH 隧道访问）。按需改这些默认值。
- 验收客户端或网络（可留空）：<例如 Windows 上的 v2rayN、家宽，或一台可供测试的外部主机>

从已有 SSH 配置和主机实测补全信息。缺少当前阶段所需的信息时，集中问我能推进这一步的问题，收到回复后接着做。可独立进行的探测或配置继续进行。通过已有授权的工具操作 DNS 和云防火墙。遇到权限或交互限制时，告诉我具体要在哪个控制台完成哪一步、应看到什么结果，然后接手验证。密码、私钥、API Token、含凭据的节点链接和面板入口路径保存在私有环境中。初始密码由我在可信终端输入。如果发现目标已有业务或无法确认主机身份，先请我确认目标和变更范围。

1. 建立 SSH 管理通路

   - 通过厂商控制台或已知可信通路核对 SSH 主机密钥指纹。若只有初始密码，优先通过厂商注入公钥，或用交互式 SSH 登录后把公钥追加到目标账号的 authorized_keys。若你的执行环境无法交互，把公钥和一条可在控制台执行的安装命令给我，我完成后你继续。复用我指定的密钥或生成这台 VPS 专用的 Ed25519 密钥，私钥留在操作者的本机或已授权的密钥存储中。
   - 在操作机的 OpenSSH 用户配置中建一个独立 Host 档案，设置 HostName、User、Port，以及对应的 IdentityFile 和 IdentitiesOnly yes（独立密钥时）。沿用现有 Include 结构，处理同名或通配配置的影响。用 ssh -G 核对生效值，并以 ssh <别名> 作为后续入口。如果你的执行环境是临时的，收集我管理电脑上的 SSH 公钥，为它开通访问，并交付对应的档案片段。限制初始登录方式之前，确认我也能用自己的密钥连上。
   - 保持原 SSH 会话或控制台可用。新开独立会话实测仅凭公钥登录和 sudo。如果初始账号是 root，先配置并验收有 sudo 权限的日常管理账号，再限制 root 登录。验证新通路后，检查 sshd -t 和实际用户的 sshd -T 生效值，关闭密码及键盘交互认证，重载并再次用独立会话验证。记录系统版本、架构、虚拟化、地址、接口、空闲资源、监听和云防火墙，用于后续选型和回退。

2. 部署标准 BBRv3

   - 上游：https://github.com/byJoey/Actions-bbr-v3 。按执行时的支持矩阵检查发行版、架构、虚拟化和引导方式。核对 /boot 空间、Secure Boot、DKMS、磁盘及网卡驱动，确认有可用的厂商救援控制台和旧内核启动项。需要重启前记录回退方式。共享宿主内核或不能安全切换内核时，保留可用的发行版内核，检查其提供的 TCP 拥塞控制，并如实报告 BBRv3 的状态。继续其他可执行步骤。
   - 从上游选匹配架构的标准发布版，固定下载版本，下载并审阅安装脚本，核对上游提供的校验信息。日常代理以标准 BBRv3 + fq 为基线。保留发行版内核和启动项，确认包配置、initramfs 和引导更新成功后重启。恢复后实测 SSH、网卡和默认路由，用 uname -r、项目状态检查、可用的 tcp_bbr 版本信息、sysctl 和 tc qdisc 核对运行中的内核、拥塞控制和实际出网队列。确认设置会在开机生效。BBR 这一步优化内核 TCP，Hysteria 2 的 QUIC 表现要单独验收。

3. 按需评估 tcpfit

   - 上游：https://github.com/Kylin010/tcpfit 。默认沿用上一步验收过的基线。若我指定启用，或基线显示吞吐、负载延迟或整形可能有改善空间，再收集 VPS 用途（此处默认 proxy）、额定带宽和方向、已知限速、主要使用线路及实测 RTT。若要测速或扫描拐点，再问可授权使用的 iperf3 对端（地址、端口）和流量预算。可以实测补全的值先测，缺数据时保留基线并说明缺项。
   - 审阅并固定 tcpfit 版本。先记录 sysctl、路由和 qdisc，再按上游子命令做基础调优、同线路对比，只有实测有收益且符合流量预算时才保留整形。让重叠的 sysctl、队列和整形各有明确的持久化来源，避免 Actions-bbr-v3 的额外 TCP 调优与 tcpfit 在开机时互相覆盖。记录 tcpfit 的调优前快照和 rollback 方法，回归时恢复已验证的设置。

4. 根据域名条件准备节点地址和证书

   - Cloudflare 托管：节点记录用 DNS only（灰云），A 指向 VPS 的公网 IPv4。只有端到端 IPv6 就绪且完成验收时才加 AAAA。为域名签可信证书时优先复用已授权、作用域限于该 Zone 的 DNS 凭据做 DNS-01。普通 Cloudflare HTTP 代理留给明确需要代理的独立 Web 主机名。参考 https://developers.cloudflare.com/dns/proxy-status/ 。
   - 其他 DNS 托管商：同样使用直连解析，优先用该托管商支持的 DNS-01。没有可用 API 时，若能持续满足 TCP 80 校验条件，可以用 HTTP-01 并配置自动续签。需要我手动改记录时，给出名称、类型和目标值，等权威 DNS 及外部解析符合预期后继续。
   - 无域名：REALITY 客户端用 VPS 公网 IP 连接，另选一个经实测兼容且同时匹配 target 和 SNI 的 TLS 1.3 目标。Hysteria 2 优先评估可自动续签的公网 IP 证书，核对 IP SAN、ACME 客户端和实际代理客户端的兼容性；也可使用客户端明确支持的私有 CA 或证书指纹固定，并通过已验证的 SSH 通路分发信任材料。问清我的客户端支持哪种方案。证书校验必须有效；无法建立信任时，向我索取可用域名或兼容客户端。参考 https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability 和 https://v2.hysteria.network/docs/advanced/Full-Client-Config/ 。

5. 按需部署 1Panel

   - 选装时使用官方稳定版 https://1panel.pro/docs/v2/installation/online_installation/ 。先规划监听。公网 TCP 443 留给 REALITY，OpenResty 等本机 TLS 后端可用回环 8443。1Panel 使用独立管理端口，默认经 SSH 管理，启用独立凭据和二次验证。如果我明确需要通过域名访问，按域名与 DNS 条件配置 HTTPS 管理入口，并验证访问限制。复查安装后 Docker、OpenResty 与防火墙的实际监听和端口映射。

6. 部署 3x-ui 和两个入站

   - 选用与客户端兼容的 3x-ui 正式版及其 Xray-core，审阅安装脚本，记录版本。安装前先限制管理端口的外部访问。设独立管理端口、强密码和私有入口路径。保存配置用当前版本支持的面板或 API，测试生成的 Xray 配置并核对实际监听和订阅；由 3x-ui 持久管理入站。上游：https://github.com/MHSanaei/3x-ui/releases 和 https://docs.sanaei.dev/docs/config/inbounds/ 。
   - REALITY：配置 VLESS + TCP/RAW + REALITY，使用公网 TCP 443。客户端支持时两端都使用 xtls-rprx-vision。生成独立 UUID、密钥对和 Short ID，核对客户端公钥、Short ID、指纹、SNI 和目标证书。使用自有站点时，先验收回环 TLS 后端的 TLS 1.3、SNI 和 ALPN，再指向该后端。云端公网 IP 由 NAT 映射时，在可绑定的本机 IPv4 地址上监听，并实测外网 443。与 HTTPS 站点共用 443 时，也要实测普通 HTTPS 回落。
   - Hysteria 2：选择空闲固定 UDP 端口，配置 v2 入站、独立高强度认证及客户端可验证的证书。先测固定端口，再加一段专用且无冲突的 UDP 跳跃范围。客户端必须实际支持并加载该范围。客户端也支持 Salamander 时，使用单独密钥配置混淆，两端参数保持一致。证书续签后自动重载使用它的服务，并演练重载验证。
   - 跳跃及防火墙：先备份当前生效规则和持久化配置，核对云安全组、主机入站网卡、iptables 后端及 Docker/1Panel 规则。使用 iptables 时，在入站接口的 nat/PREROUTING 将专用 UDP 范围 REDIRECT 到固定监听端口，核对 NAT 后的过滤链已允许目标 UDP 端口。云安全组放行固定 UDP 端口及跳跃范围，保留 SSH 和 TCP 443。用现有加载机制固化 iptables 规则（由 netfilter-persistent 管理时写回其启动规则）。已有原生 nftables 管理时，用同一套配置写入等效规则并持久化。仅配置所用地址族，核对另一地址族的面板暴露情况。避免重复规则、清空整张规则表或把其他服务的临时规则存成开机规则。参考 https://v2.hysteria.network/docs/advanced/Port-Hopping/ 。
   - 关闭 3x-ui 公网直连（可选，默认开启这项保护）：先通过 SSH 本地转发实际打开登录页，再把管理监听绑定到 VPS 的 127.0.0.1，并收掉云端与主机防火墙上的原生管理端口放行。给我一条可复用的 ssh -NT -L 命令。HTTPS 地址保留证书上的名称以通过校验。若我选择保留公网入口，先收集可信管理来源并按其范围放行，用可验证的 HTTPS。面板和订阅监听分别核对，订阅按我指定的访问方式提供。

7. 复测并交付

   - 从外部客户端分别以真实凭据通过 REALITY 和 Hysteria 2 发起 HTTPS 请求，核对实际代理出口 IP。固定 UDP 端口与跳跃范围分开测，抽测范围两端及中间，在持续流量下覆盖多个跳跃周期，用客户端日志或规则计数确认确有换端口。优先用我的日常网络，也记录可用的独立外部网络。只有 VPS 本机探测或端口扫描时，把客户端验收标记为待测，告诉我需要哪个客户端或网络来补测。
   - 从外网验证预期开放的服务，以及预期关闭的管理端口。验证 SSH 隧道仍能打开面板，已有站点或启用的订阅也要核对。最终重启 VPS 后，重新连 SSH，复查新内核和队列、服务开机启动、证书、监听与防火墙/NAT，再重测两个节点、跳跃和管理入口。若某步失败，按备份恢复对应变更并复测。
   - 在最终说明中逐项交付实际可用的访问方式。我应能按步骤从自己的设备连接。
     - 3x-ui：给出已验证的入口。走 SSH 隧道时，给出完整转发命令、浏览器应打开的地址，以及 HTTPS 证书名称需要的本地映射。入口路径和初始账号从私有记录获取。
     - 1Panel（已安装时）：给出已验证的 HTTPS 入口或 SSH 转发命令及打开方式，说明从哪里领取初始账号及完成二次验证。管理凭据和入口路径通过私有渠道提供。
     - REALITY 和 Hysteria 2：分别写明服务器地址、协议、TCP/UDP 端口和适用的客户端。说明如何导入链接或配置、选中节点并验证出网，指出 Hysteria 2 固定端口与跳跃范围的用法。含认证信息的链接、二维码、订阅或配置文件存放在私有位置，并告诉我如何获取。
   - 一并交付 SSH 别名、各组件版本、证书续签和重载方式、防火墙持久化位置、备份与回滚位置。逐项写明实际测试来源和结果，以及缺少的信息或未通过的项目。
```
