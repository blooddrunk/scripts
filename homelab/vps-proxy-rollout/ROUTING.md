# 3x-ui 路由说明

先区分两层。客户端分流决定请求走本地网络还是交给 VPS。3x-ui 下的 Xray 路由处理已经进入 VPS 的代理流量。`direct` 是 VPS 自己连接目标，`blocked` 会丢弃匹配的请求。防止办公或国内流量被错误送到 VPS，首先依赖客户端分流。

## 现有规则与用途

四台现有 VPS（`raksmart`、`bitsflow`、`lightlayer`、`lightlayer-zh`；`nosla` 已退役）依下表顺序匹配，首条匹配的规则生效。办公域名、健康检查和 `geoip:cn` 的匹配范围限于当前 Reality 和 Hysteria 2 入站。`lightlayer-zh` 上线即采用同一规则链，gated 入站为原 Hysteria 2 入站与 `in-443-tcp`（旧 Reality 入站退役时标签已一并清理）。

| 顺序 | 规则 | 用途与适用条件 |
| --- | --- | --- |
| 1 | 本地 `api` 入站 → `api` | 交给 Xray 的内部管理接口。3x-ui 用它查询统计等，保留面板生成的规则即可 |
| 2 | `geoip:private` → `blocked` | 拒绝代理用户请求私网与回环地址，减少借 VPS 访问内部服务的风险。公网代理宜保留。需要访问特定内网服务时单独限定入站、目标和权限 |
| 3 | `protocol: bittorrent` → `blocked` | 拒绝 Xray 识别出的 BT 流量，按服务商条款与自己的用途决定是否启用。识别范围取决于嗅探，对隐藏或未识别的流量覆盖有限 |
| 4 | 办公域名后缀 → `direct` | 给确实要经 VPS 访问的办公服务留例外。某些域名解析到中国大陆 IP，靠它提前通过后面的 IP 阻断。新 VPS 按自己的客户端分流需求配置 |
| 5 | 指定 AliDNS 地址的 UDP 53 → `direct` | 给当前 daed 的 UDP 健康检查留一条窄例外，避免代理节点可用却因探测被阻断而被判离线。仅当客户端经这些代理向该地址探测且后续规则会挡住它时需要。更换探测地址时连同此规则验收 |
| 6 | `geoip:cn` → `blocked` | 以 VPS 侧的 GeoIP 数据挡住发往中国大陆 IP 的代理流量，作为客户端误分流时的兜底。属于部署策略，Reality 和 Hysteria 2 本身用不到它。启用后需检查大陆 CDN、DNS 和所需服务的例外 |

`domainStrategy: IPOnDemand` 使 Xray 在需要判定 IP 规则时尝试解析域名。因此，域名请求也可能命中 `geoip:cn`。地区判定会随解答、线路和 GeoIP 数据变化。域名级 `geosite:cn` 曾误拦连通性测试和正常海外服务，现有配置已移除此项。

默认出口是 `direct`（Freedom）。它还有自己的 `finalRules` 私网保护，可校验出站时命中的地址，覆盖一部分从域名解析到私网的情形。对外代理通常保留这一层，同时验证使用的 Xray 版本和出站链路。 [Freedom 出站实现](https://github.com/XTLS/Xray-core/blob/v26.11.9/proxy/freedom/freedom.go)

从空白机开始时，先保留面板生成的 API 规则与适用的私网保护。BT 根据服务商条款选择。采用客户端分流的部署，可以在确实需要服务端 IP 兜底时再加 `geoip:cn`，并为受到影响的实际业务和探测补齐例外。

## 办公例外什么时候可以删

当前四台（含 2026-11-23 上线的 `lightlayer-zh`）都保留了 `geoip:cn` 和办公例外，Xray 统一为 26.11.9。两台办公路由器生效的规则仍把受测办公域名送往代理。在先行的四台（含当时在役的 `nosla`）上分别用同版本 Xray、GeoIP 和 DNS 做隔离对照，保留该例外时，受测站点命中 `direct`。仅移除该例外后，其中一个站点在四台全部命中 `blocked`。因此，当前仍需保留这组例外。

如果以后办公线路上的相关站点都能按客户端规则直接访问，或迁到另一个允许这些请求的出口，先用实际客户端验证登录、资源加载和依赖域名。再逐台备份并对照测试移除例外后的真实路由与请求。采用同一方法复核 UDP 健康检查，保留仍被探测使用的例外。 [客户端分流顺序](../openwrt-dns-daed/docs/principles.md)
